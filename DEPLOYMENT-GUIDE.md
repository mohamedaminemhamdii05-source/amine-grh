# Amine GRH: publish on GitHub and host the demo for free

A step-by-step guide from zero. Total cost: **0 €**. Time: about **45 minutes**.

What you will get:
- **Source code** on GitHub: `https://github.com/<you>/amine-grh`
- **Live demo**: `https://amine-grh.onrender.com` (or a similar address), with fictional data and one-click demo logins

Free services used:

| Service | What it does | Plan |
|---|---|---|
| GitHub | stores and shows your code | free |
| MongoDB Atlas | the online database | free M0 cluster |
| Render | runs the app (backend + website) | free web service |

---

## Part A: Before you start

1. **Stop the app on your PC** if it is running (Ctrl+C in its windows).
2. **Check Git is installed**: open PowerShell and run `git --version`. You should see a version number.
   If not, install it from https://git-scm.com/download/win (keep the default options).
3. Have an **email address** ready for the three accounts.

### The demo accounts (public, fictional)

The online demo loads fictional data automatically (5 employees, 4 client companies, 4 projects with task boards)
and shows these logins on the login page, with one-click buttons:

| Role | Email | Password |
|---|---|---|
| Admin | `admin@aminegrh.demo` | `Demo@2026` |
| Employee | `employee@aminegrh.demo` | `Demo@2026` |

- Visitors can try everything, but they **cannot change the demo logins' email/password**, or delete them.
- The demo data **resets every time the server starts**. On the free plan the server sleeps after about 15 minutes
  without visitors and starts again on the next visit, so the demo cleans itself regularly.
- Demo mode is only switched on online (`DEMO_MODE=true` in `render.yaml`). It is never active on your PC,
  so your real local data is safe.

## Part B: Put the code on GitHub

### B1. Create a GitHub account
Go to https://github.com and sign up. Choose your username carefully: it appears in your links.

### B2. Tell Git who you are (once per PC)
Your name and email are stored in every commit and are **public**. To keep your email private, use GitHub's
"noreply" address: GitHub > Settings > Emails > tick **Keep my email addresses private** and copy the address
shown there (it looks like `12345678+username@users.noreply.github.com`).

```powershell
git config --global user.name "Mohamed Amine"
git config --global user.email "YOUR-NOREPLY-ADDRESS@users.noreply.github.com"
```

### B3. Create an empty repository
1. On GitHub, click **+** (top right) > **New repository**.
2. Repository name: `amine-grh`
3. Description: `HR management web app - Angular, Node.js/Express, MongoDB`
4. Choose **Public**.
5. **Do not** tick "Add a README", ".gitignore" or "license" (the project already has them).
6. Click **Create repository**. Keep the page open: it shows your repository address.

### B4. Upload the project
In PowerShell, run these one by one (replace `YOUR-USERNAME`):

```powershell
cd "C:\Users\Mega Pc\Desktop\amine-grh\amine-grh"
git init
git add .
git status
```

**Check the `git status` list before continuing.** It must NOT contain `.env`, `node_modules` or `dist`.
(The project's `.gitignore` already excludes them; this is a safety check.)

```powershell
git commit -m "Amine GRH - HR management app"
git branch -M main
git remote add origin https://github.com/YOUR-USERNAME/amine-grh.git
git push -u origin main
```

The first `git push` opens a browser window to sign in to GitHub. Sign in and approve. Then refresh your
repository page: your files are there.

## Part C: Create the free database (MongoDB Atlas)

### C1. Sign up
Go to https://www.mongodb.com/cloud/atlas/register and create an account (you can use "Sign up with Google").

### C2. Create a free cluster
1. Choose **M0 (Free)**.
2. Provider: any (AWS is fine). Region: one close to you (for example Frankfurt or Paris).
3. Name: `amine-grh`. Click **Create Deployment**.

### C3. Create a database user
Atlas asks for a database user right away (or go to **Security > Database Access**):
1. Username: `amine-grh`
2. Click **Autogenerate Secure Password** and **copy the password** somewhere safe.
   (Autogenerated passwords use only letters and numbers, which keeps the connection string simple.)
3. Click **Create Database User**.

### C4. Allow Render to connect
Go to **Security > Network Access** > **Add IP Address** > **Allow access from anywhere** (`0.0.0.0/0`) > **Confirm**.
(Render's free servers don't have a fixed address, so this is required. The database is still protected by
the username and password.)

### C5. Copy the connection string
1. Go to **Database > Clusters** > **Connect** > **Drivers**.
2. Copy the string. It looks like:
   ```
   mongodb+srv://amine-grh:<db_password>@amine-grh.xxxxx.mongodb.net/?retryWrites=true&w=majority&appName=amine-grh
   ```
3. Replace `<db_password>` with the password from C3, and add the database name `amine-grh-demo`
   **right after `.net/`** (before the `?`):
   ```
   mongodb+srv://amine-grh:YOURPASSWORD@amine-grh.xxxxx.mongodb.net/amine-grh-demo?retryWrites=true&w=majority&appName=amine-grh
   ```
Keep this final string: it is your `MONGO_URI`. **Never put it in your code or on GitHub.**

> This database is only for the public demo: demo mode erases it and reloads the demo data on every start.

## Part D: Host the app (Render)

### D1. Sign up
Go to https://render.com and click **Get Started**, then **GitHub** (sign up with your GitHub account).

### D2. Deploy with the Blueprint (uses the project's `render.yaml`)
1. In the Render dashboard, click **New +** > **Blueprint**.
2. Connect your GitHub account if asked, and give Render access to the `amine-grh` repository.
3. Select the `amine-grh` repository. Render reads `render.yaml` and shows one service: `amine-grh` (Free).
4. It asks for **MONGO_URI**: paste the connection string from C5.
   (`SECRET_KEY` is generated automatically; `DEMO_MODE`, `NODE_VERSION`, etc. are already set.)
5. Click **Apply** / **Deploy Blueprint**.

### D3. Wait for the first build (5-10 minutes)
Open the service and the **Logs** tab. When it works you will see:
```
serving the frontend from ...
server work (port 10000)
connected
demo data loaded: 1 admin, 5 employees, 4 clients, 4 projects
```

### D4. Open your demo
At the top of the service page there is your address, like `https://amine-grh.onrender.com`.
Open it: the login page shows **Try the demo** with "Log in as Admin" and "Log in as Employee".

> **If Blueprint is not available**, create it manually: **New +** > **Web Service** > your repository, then:
> Runtime `Node`, Build command `cd frontend && npm install && npx ng build && cd ../backend && npm install`,
> Start command `cd backend && npm start`, Instance type `Free`, and these Environment Variables:
> `NODE_VERSION=20`, `MONGO_URI=<your string>`, `SECRET_KEY=<long random value>`, `DEMO_MODE=true`, `TRUST_PROXY=1`.
> Generate a `SECRET_KEY` on your PC with:
> `node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"`

## Limits of the free plans (good to know)

- **Sleeping**: after ~15 minutes without visitors the app sleeps; the next visit takes 30-60 seconds to wake it.
- **Uploaded photos/files are temporary**: the free plan has no permanent disk, so uploads disappear when the
  app restarts. Database data (Atlas) is kept, and the demo reloads its own data anyway.
- Free plan rules change from time to time: check Render's and Atlas's current limits if something stops working.

## Troubleshooting

| Problem | Solution |
|---|---|
| Render log: `MongoDB connection failed` | Check Network Access is `0.0.0.0/0` (C4), the password in `MONGO_URI` is right, and `/amine-grh-demo` is before the `?` |
| Render log: `SECRET_KEY is missing` | Add the `SECRET_KEY` environment variable (see D4 note) |
| Build fails with a Node version error | Make sure `NODE_VERSION` is `20` in Environment |
| Build fails with `JavaScript heap out of memory` | Add environment variable `NODE_OPTIONS` = `--max-old-space-size=460` and redeploy |
| Page takes a long time to open | Normal on the free plan after sleeping: wait up to a minute |
| "Too many login attempts" | 10 wrong passwords in 15 minutes: wait 15 minutes |
| `git push` is refused | Check the repository address in `git remote -v`, and that you signed in to GitHub in the browser window |
| No "Try the demo" box | Check `DEMO_MODE` is `true` in Render > Environment, then redeploy |
